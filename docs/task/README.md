# 任务清单

`docs/task/` 用于承接已经确认的系统设计，并把它拆成可执行、可验收、可勾选的实施任务。

这里不重复做产品定义和架构讨论，只描述“接下来具体要做什么”。

当前按可独立验收的实施闭环拆为三个阶段：

- [第一阶段：工程骨架与基础闭环](./phase-1.md)
- [第二阶段：素材库、分析与检索闭环](./phase-2.md)
- [第三阶段：文案、配音、编排与 `edit_plan` 闭环](./phase-3.md)

另外维护一份只记录近期已确认结论的任务清单：

- [已确认任务清单：素材预处理与素材库边界](./confirmed-material-library-checklist.md)

说明：
- `phase-3.md` 当前不作为最近这轮素材库与预处理讨论的依据
- 与预处理工作区、素材库边界、3 帧 VLM 输入相关的最新确认，以 `confirmed-material-library-checklist.md` 为准

使用规则：

- 这里只写实施任务，不重复做产品和架构讨论
- 设计基线以 [system-overview.md](../system-overview.md) 和 [architecture.md](../architecture.md) 为准
- 只有存在代码、测试或真实运行验证证据的事项，才允许勾选
- 每个阶段都应包含目标、任务项、验收闭环和完成标准
- 每个阶段都应尽量形成真实可跑通的最小业务链路
